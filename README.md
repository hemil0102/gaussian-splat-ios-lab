# Gaussian Splat iOS Lab

**아이폰으로 찍은 사물을 3D 스플랫으로 띄우고, 움직이게 만들기까지 15단계.**

WWDC26 세션 [279 Explore advances in RealityKit](https://developer.apple.com/videos/play/wwdc2026/279/) · [287 Build next-generation experiences with visionOS 27](https://developer.apple.com/videos/play/wwdc2026/287/) 에서 나온 `GaussianSplatComponent` 를 손으로 확인하는 학습 저장소입니다.

> **핵심 하나** — 이 API 는 **visionOS 전용이 아닙니다.** `GaussianSplatComponent` 는 **iOS 27 · iPadOS 27 · macOS 27 · visionOS 27** 에 모두 있습니다. 그래서 이 저장소는 시뮬레이터를 쓰지 않고 **아이폰 실기기**에서 전부 확인합니다.

> **핵심 둘** — RealityKit 은 **스플랫 파일을 읽어 주지 않습니다.** PLY 든 SPZ 든 직접 파싱해서 `LowLevelBuffer` 를 채워야 합니다. 그래서 이 저장소의 주제는 API 호출이 아니라 **버퍼 안 숫자의 배치**입니다.

## 프로젝트 소개

3D Gaussian Splatting 은 장면을 **삼각형이 아니라 «뿌연 타원체» 수십만 개**로 표현합니다. 타원체 하나가 위치·크기·회전·불투명도·색을 갖고, 이것들을 뒤에서 앞으로 겹쳐 그리면 사진처럼 보입니다. 잎사귀·털·구겨진 천처럼 **폴리곤으로는 지옥인 형상**이 스플랫에겐 오히려 유리합니다.

### API 지원 현황

| 심볼 | 하는 일 | 최소 버전 |
|---|---|---|
| [`GaussianSplatComponent`](https://developer.apple.com/documentation/realitykit/gaussiansplatcomponent) | 스플랫 데이터를 그리는 컴포넌트 | iOS · iPadOS · macOS · visionOS **27** |
| [`GaussianSplatResource`](https://developer.apple.com/documentation/realitykit/gaussiansplatresource) | 데이터 + 렌더 옵션(활성화 함수·정렬·색공간) | 27 |
| `GaussianSplatResource.BufferResource` | 버퍼로 서술한 스플랫 묶음. **개수 상한을 넘으면 throw** | 27 |
| [`GaussianSplatResource.BufferDescriptor`](https://developer.apple.com/documentation/realitykit/gaussiansplatresource/bufferdescriptor) | 한 속성이 버퍼 안 어디에 있는가 (**바이트** 단위 stride·offset) | 27 |
| [`LowLevelBuffer`](https://developer.apple.com/documentation/realitykit/lowlevelbuffer) | GPU 가 읽는 날것의 버퍼 | iOS **26** |

**알아 둘 성질 넷**

1. **개발자가 만지는 셰이더가 없습니다.** `ModelComponent` 와 달리 커스텀 머티리얼을 붙일 수 없습니다.
2. **씬 조명이 안 먹습니다.** 색은 촬영 당시 조명 그대로 구워져 있습니다. (11단계에서 눈으로 확인)
3. **개수 상한이 있습니다.** 정확한 숫자는 공개돼 있지 않고 `BufferResource` 초기화가 `throw` 로 알려 줍니다.
4. **버퍼를 복사하지 않고 «참조» 합니다.** 그래서 버퍼 내용을 바꾸면 스플랫이 움직입니다. (13단계)

## 스플랫 소재 준비

**1·2부(00~06)에는 파일이 필요 없습니다.** 8단계 전까지 여유 있게 준비하세요. 촬영은 **6단계쯤 왔을 때** 하시면 딱 맞습니다.

### 촬영

| | |
|---|---|
| **대상** | 표면에 무늬가 있고, 한 바퀴 돌 수 있고, 반사·투명이 없는 것. **화분에 심은 식물**이 가장 좋습니다 |
| **바퀴** | 눈높이 · 내려다보는 각 · 올려다보는 각, **세 바퀴** |
| **핵심** | 사물은 두고 **사람이 돕니다.** 손에 들고 돌리면 SfM 이 카메라 위치를 반대로 풉니다 |
| **잠글 것** | 노출·초점·화이트밸런스 (길게 눌러 AE/AF LOCK). 조명이 각도마다 바뀌면 학습이 «방향에 따라 색이 변하는 표면» 으로 잘못 배웁니다 |

### 스플랫 만들기

**[Scaniverse](https://apps.apple.com/app/id1541433223) (무료, iOS)** — 촬영부터 학습까지 폰 안에서 몇 분. PLY 내보내기 지원. **첫 스캔은 무조건 이걸로 하세요.** 맥에서 학습을 돌리면 실패했을 때 원인이 촬영·SfM·학습 셋으로 흩어집니다.

맥 로컬 학습(RadianceKit · OpenSplat · Brush + COLMAP)은 화질을 올리고 싶어졌을 때, 또는 10단계에서 개수 상한에 걸렸을 때 갑니다.

### 0. 기준선 — 흰 큐브 하나

**⏱ 10분 · 목표** — 아이폰 화면에 흰 큐브 하나.

나중에 스플랫이 안 보일 때 **«RealityView 자체가 안 뜬 건지» 를 가르기 위한 기준선**입니다. 오디오 랩에서 해 보신 것과 같으니 오래 붙들지 마세요.

- AR 없이, 고정 카메라로
- 기기의 GPU 패밀리를 로그로 찍어 **Apple7 이상**인지 확인

**눈으로 확인** — 큐브가 보이고, 기기를 기울여도 그 자리에 있다.

### 1. 스플랫 하나를 «숫자로»

**⏱ 20분 · 목표** — `Float` 열넷을 만들어 **화면에 표로 찍기.** 아직 3D 가 아닙니다.

이 저장소의 주제가 «숫자의 배치» 라서, 그 숫자부터 눈으로 봅니다. `Text` 로 찍는 게 전부예요.

| 속성 | 값 | 개수 |
|---|---|---|
| Position | x, y, z | float 3 |
| Scale | x, y, z | float 3 |
| Rotation | r, x, y, z (쿼터니언) | float 4 |
| Opacity | 하나 | float 1 |
| Spherical Harmonics (0차) | r, g, b | float 3 |

- 이 열넷을 담을 **Swift 타입을 하나 만듭니다** — 이름과 모양은 설계 대화에서 정합니다
- 각 값의 «그럴듯한 범위» 를 주석으로 적어 둡니다. 이게 나중에 파서를 디버깅할 때 잣대가 됩니다
- 화면에 이름·값·바이트 수를 표로 띄웁니다

**눈으로 확인** — 열네 개 값이 화면에 보이고, 합계가 **56바이트**로 찍힌다.

**⭐️ 즉흥 실험** — `MemoryLayout<그 타입>.size` 와 `.stride` 를 나란히 찍어 보세요. 둘이 다른가요?

---

### 2. 버퍼에 넣고 다시 꺼내기

**⏱ 30분 · 목표** — `LowLevelBuffer` 에 써넣고 **그대로 읽어 나오는지** 확인. **아직 그리지 않습니다.**

바이트를 처음 만지는 자리입니다. 여기서 3D 까지 같이 하면 실패했을 때 원인을 못 가리므로, **왕복만** 확인합니다.

- `LowLevelBuffer` 를 만들고 `withUnsafeMutableBytes` 로 1단계의 값을 써넣습니다
- 다시 읽어서 **1단계의 표와 나란히** 화면에 띄웁니다
- 두 열이 같으면 통과

**눈으로 확인** — 「넣은 값 / 꺼낸 값」 두 열이 열네 줄 다 일치. 하나라도 다르면 여기서 잡습니다.

**⭐️ 즉흥 실험** — 읽을 때의 시작 위치를 **4바이트만 밀어** 보세요. 표가 어떻게 어긋나나요? (5단계에서 이 장면이 다시 나옵니다)

## 2부 · 첫 타원체

---

### 3. ★ 첫 스플랫을 그린다

**⏱ 40분 · 목표** — 화면에 **뿌연 타원체 하나.**

2단계까지 확인된 버퍼에, «어느 바이트가 무슨 속성인지» 를 알려 주면 그려집니다.

- `BufferDescriptor` 다섯 개 — position · scale · rotation · opacity · sphericalHarmonics
- `BufferResource` → `GaussianSplatResource` → `GaussianSplatComponent`
- ⚠️ `BufferResource` 초기화는 **`throws`** 입니다. `try!` 를 쓰지 말고 에러를 화면에 띄우세요

**안 보이면 볼 곳** — ① 엔티티가 카메라 밖(scale 을 0.1~1 로 훑기) ② opacity 가 0 에 가까움 ③ descriptor 의 offset·stride

**눈으로 확인** — 뿌연 덩어리 하나. 기기를 돌리면 **어느 각도에서는 납작해집니다.**

---

### 4. 타원체를 만져 보기

**⏱ 20분 · 목표** — 슬라이더로 값을 바꿔 보며 «타원체가 어떻게 생겼는지» 를 몸으로 안다.

- scale x·y·z 슬라이더 셋
- opacity 슬라이더
- 회전 슬라이더 하나

값을 바꾸면 버퍼를 다시 쓰게 되는데, **이게 13단계 애니메이션의 예고편**입니다.

**⭐️ 즉흥 실험** — `scale` 을 `(0.5, 0.02, 0.5)` 로 두고 옆에서 보세요. 무엇이 되나요?

---

### 5. 열 개, 그리고 stride

**⏱ 30분 · 목표** — 하나를 열 개로. 그리고 **일부러 틀려 보기.**

하나에서 열 개가 되는 순간 «버퍼 안 어디부터 다음 스플랫인가» 가 문제가 됩니다. 그게 `stride` 입니다.

- `stride` 와 `offset` 은 **바이트 단위**입니다 — 개수가 아닙니다
- 정렬 때문에 실제 stride 가 값의 합보다 클 수 있습니다 (56 vs 60)

**먼저 해 보기** — `offset` 을 4바이트 밀면 화면이 어떻게 될 것 같나요? 예측하고 **실제로 밀어 보세요.** 색이 위치가 되고 위치가 회전이 되는 광경을 한 번 봐 두면, 9단계에서 PLY 가 안 뜰 때 바로 알아봅니다.

**눈으로 확인** — 열 개가 규칙적으로 늘어선다. **틀린 화면은 스크린샷으로 남겨 Q&A 에 붙입니다.**

---

### 6. 색 — 구면조화와 활성화 함수

**⏱ 30분 · 목표** — 타원체에 색을 넣고, **왜 날값을 그냥 넣으면 안 되는지**를 본다.

PLY 안의 값은 날것입니다. `opacity` 는 시그모이드 이전의 로짓, `scale` 은 로그 스케일, 색은 SH 0차 계수라 그대로 RGB 가 아닙니다.

- SH 0차 계수 → RGB
- **`GaussianSplatResource` 에 스케일·불투명도의 «활성화 함수» 옵션이 있습니다.** 손으로 exp/sigmoid 를 돌리기 전에 이 옵션부터 확인합니다

**먼저 해 보기** — 날값을 그대로 넣고 한 번 실행해 보세요. 검은 덩어리인가요, 거대한 흐린 구름인가요? **그 화면이 9단계에서 다시 나옵니다.**

이제 **촬영할 때**입니다. 8단계까지 스캔 파일이 있어야 합니다.

---

## 3부 · 많이, 그리고 파일에서

---

### 7. 규칙으로 만든 구름

**⏱ 30분 · 목표** — 프로시저럴로 1만 개. **내 아이폰이 몇 개까지 부드러운지 찾는다.**

파일 없이 성능 감각을 먼저 얻는 자리입니다.

- 나선·구·격자 중 하나로 좌표를 계산해 버퍼를 채웁니다
- 화면에 **개수 · FPS · 버퍼 바이트 수**를 띄웁니다
- 렌더 비용은 **개수 × 오버드로** 입니다

**눈으로 확인** — 60fps 가 유지되는 개수를 찾아 PROGRESS 에 적습니다. **그 숫자가 10단계의 기준선입니다.**

**⭐️ 즉흥 실험** — 개수는 그대로 두고 불투명도를 전부 `0.05` 로 낮춘 뒤, 카메라를 구름 «안» 으로 넣어 보세요. 개수가 같은데 왜 느려질까요?

---

### 8. PLY 헤더 읽기

**⏱ 30분 · 목표** — 본문은 건드리지 않고 **헤더 텍스트만** 파싱해 화면에 표로.

PLY 는 앞부분이 사람이 읽을 수 있는 텍스트입니다.

- `element vertex N` 에서 개수
- `property float x` 같은 줄들의 **순서**가 곧 본문의 바이트 순서
- 3DGS 표준 PLY 의 필드 순서는 **우리 배치와 다릅니다** — 여기서 발견하는 것이 요점

**먼저 해 보기** — 자기 스캔 파일의 헤더를 텍스트 에디터로 먼저 열어 보세요. 필드가 몇 개인가요? 그중 우리가 1단계에서 쓴 것은 몇 개인가요?

**눈으로 확인** — 「스플랫 N개 · 필드 M개」 와 필드 이름 목록이 화면에.

---

### 9. ★ 내가 찍은 물건이 뜬다

**⏱ 60분+ · 목표** — PLY 본문을 읽어 화면에.

앞의 여덟 단계가 전부 이 한 화면을 위한 준비였습니다.

- 헤더가 알려 준 순서대로 본문을 읽어 우리 배치로 **재배치**
- 6단계의 활성화 함수를 적용
- 엔디안 · `Float` 크기 · 정렬을 확인

**막히면 볼 곳** — 화면이 비면 5단계의 «틀린 offset 화면» 과 6단계의 «날값 화면» 중 어느 쪽을 닮았는지 보세요. 둘 다 아니면 파서가 개수를 잘못 읽은 것입니다.

**눈으로 확인** — 스캔한 물건이 보인다. 손가락으로 돌려 뒤도 본다.

---

### 10. 개수 줄이기

**⏱ 30분 · 목표** — 상한에 걸렸을 때, 그리고 느릴 때 쓸 카드 셋.

- `BufferResource` 가 던지는 에러를 **잡아서 화면에 표시**
- **저불투명 스플랫 컬링** — 오버드로에 직접 듣습니다
- **half precision** — 메모리 절반

**눈으로 확인** — 컬링 전/후의 개수와 FPS 를 나란히 띄우고 비교합니다.

## 4부 · 씬에 놓고 움직이기

---

### 11. 놓고 만지기

**⏱ 30분 · 목표** — 씬 안의 «물건» 답게. 그리고 **조명이 안 먹는다** 를 눈으로.

- `Transform` 으로 위치·크기, 드래그로 회전, 핀치로 확대
- `GroundingShadowComponent` — 구형 프록시로 근사 그림자. 붕 떠 보이는 걸 막는 가장 싼 방법
- 옆에 `ModelEntity` 구를 하나 놓고 **조명 세기 슬라이더**를 답니다

구는 밝아지는데 **스플랫은 미동도 없습니다.** «알고 있다» 와 «봤다» 는 다릅니다.

**⭐️ 즉흥 실험** — 어두운 씬에 밝게 찍은 스플랫을 놓아 보세요. 어떻게 하면 덜 어색해질까요? (촬영 단계에서 할 수 있는 일이 하나 있습니다)

---

### 12. 엔티티를 움직인다

**⏱ 20분 · 목표** — 가장 쉬운 층위의 애니메이션.

스플랫 엔티티도 평범한 `Entity` 입니다. `Transform` 애니메이션·물리·제스처가 그대로 듣습니다. **실용 케이스의 9할이 여기서 끝납니다.**

**눈으로 확인** — 돈다. **형태 자체는 굳어 있다**는 것도 확인합니다.

---

### 13. ★ 버퍼를 갱신한다

**⏱ 40분 · 목표** — 진짜 스플랫 애니메이션.

Apple 문서의 한 줄이 근거입니다 — *「프레임워크는 리소스의 버퍼를 복사하지 않고 참조하므로, 하부 `LowLevelBuffer` 의 내용을 갱신해 스플랫을 시간에 따라 애니메이션할 수 있습니다.」*

- 가장 쉬운 것부터 — **opacity 버퍼만** 시간축으로 조작
- 높이(y)에 따라 순서대로 나타나게 하면 «아래에서 위로 차오르는» 등장 연출
- 4단계에서 슬라이더로 했던 일을, 이번엔 시간이 대신합니다

**먼저 해 보기** — 1단계에서 우리는 한 버퍼에 값을 죽 이어 붙였습니다. opacity 만 매 프레임 바꾸려면 그 배치가 불리할까요, 상관없을까요?

**눈으로 확인** — 아래에서 위로 차오르며 나타난다.

### 14. 형태를 흔든다 (선택)

**⏱ 40분 · 목표** — position 버퍼를 건드려 형태를 바꾼다.

- 사인파로 좌우로 흔들기 — 바람 맞는 잎
- **프레임 시퀀스 재생 맛보기** — 여러 PLY 를 미리 버퍼로 만들어 두고 갈아끼우면 4DGS 가 됩니다
